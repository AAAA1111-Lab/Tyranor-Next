# 共用画质滤镜链

## 功能与设置

全局和单游戏使用同一套有序滤镜链，最多八个节点；可添加、移除、上下移动和长按拖拽排序。单游戏切换跟随全局时保留自定义链，切回可继续使用。菜单按算法分类，带多个预设的分类提供二级选择，单个滤镜直接添加。界面继续使用项目公共组件和 Miuix；参数弹窗复用 `AppAlertDialog`、`SlidingTabRow`、`AppSearchField` 与 `DialogMiuixSlider`。后者是 Miuix 0.9.2 无法关闭拇指按压动效的兼容适配，交互由外层承接以遵守弹窗无反馈规范。

适应缩放按照输入比例计算当前屏幕内可容纳的最大尺寸；固定原生倍率的模型保留训练输出倍率，超出屏幕时由显示层 Resize 等比适配。自定义缩放仅提供一个 0.25–4 倍的等比倍率；旧版横纵不同的配置按较小倍率统一，沿用已有存储和启动协议字段。CAS 额外提供锐度参数。CuNNy2 的 4x32 / 8x32 两个较重预设不提供菜单入口，旧配置中的对应节点移除，其余节点保留。

性能分析器使用顶部或底部居中的单行条：GPU / 帧率与输入尺寸 → 带简称、非 1X 倍率 `(2X)` 和 GPU 用时的滤镜色卡 → 必要时灰色 Resize 色卡 → 最终显示尺寸。仅在滤镜启用且所选内核支持时可选；数据刷新间隔使用预设菜单，默认两秒。颜色来自各滤镜定义，与排序无关；蓝色用于线条重建，绿色用于降噪，橙色用于锐化，紫色用于神经放大，灰色 Resize 表示未计时的默认显示处理。未提供可靠 GPU 时间时显示缺失值，不代用 CPU 提交时间。单节点及总 GPU 耗时丢弃超过 1000 ms 的异常数据，不计入均值或清空已有正常样本；汇总超过同一上限时显示缺失值。计时失效事件仍清空对应样本，零值与 1000 ms 边界正常统计。

## 引擎接入与支持范围

### Kirikiroid2

保留项目随附的引擎二进制。宿主根据实际加载符号所在 ELF 的身份核对已知内核，并在合成纹理进入屏幕缩放前通过桥接执行滤镜；输入尺寸取实际纹理，不按屏幕尺寸推算。无法确认入口时保留正常呈现，不将屏幕尺寸伪装成原始输入。不同游戏的舞台尺寸可能是 720p 或 1080p；这些数值不代表单张背景素材尺寸。

本轮提供 Kirikiroid2 1.3.4 / 1.3.9 接入；krkrsdl3 尚未接入。启动阶段只规范化库路径并核对库名，不重新读取整库计算 SHA-256；GL 上下文建立后由 native 核对已加载映射的 GNU Build ID、符号、虚表及重定位入口。ELF note 仅从可读加载段读取，并检查地址、对齐和长度边界。这是兼容版本识别，不是文件完整性校验；外置插件安装的 ZIP SHA-256 校验保持不变。

### Siglus

只对固定上游的构建副本应用下游补丁，不改参考仓库。新增可选舞台几何查询 ABI，由宿主把生产 Surface 限制为逻辑舞台尺寸，在验证 Surface / viewport 与舞台一致后执行共用滤镜，再呈现到等比屏幕区域。舞台包含文本、UI、转场，并非素材单层。

补丁、固定来源、旧 ABI 锚点、工具链要求及复现步骤见 [Siglus 下游补丁](../engine/patches/siglus/README.md)。旧库全部导出保留，原 `set_surface` 返回类型、窗口引用所有权和过期回调处理随接入一并修正。全部共享软渲染引擎并未重新进行真机回归，导出校验不能替代该回归。

暂停及窗口销毁仅停止步进并异步解绑输出，不在 Activity 回调里等待 GPU，也不因排队超过三秒永久标记故障。输出重连完成后恢复步进。滤镜准备阶段继续同步直接窗口的重建/尺寸变更；准备失败时等待 GLES 实际断开后，再从当前 SurfaceHolder 绑定窗口。成功绑定前保留代理及游戏实例，不重新加载游戏。

### 官方 Artemis

采用尺寸限制舞台输出路线；桥接使用宿主应用 ClassLoader 注册，设备重置后保留舞台输出尺寸。不会替换官方内核或修改其二进制。

宿主核对已加载 ELF 的 GNU Build ID 与已知库名，读取的 note 必须完整位于可读加载段中；所需符号、重定位入口和槽值仍逐项核验，身份或入口不匹配时保留原路径。这是默认打包版本的识别门槛，不是文件完整性校验，也不在启动主线程重新读取整库计算 SHA-256；外置插件安装的既有 SHA-256 流程保持不变。JNI 方法查找逐次处理异常，可用的状态入口在注册失败时上报失败，避免一直停留在等待状态。

| 用户界面版本名称 | 支持滤镜 |
| --- | --- |
| v1（Tyranor/Rev.2762） | 否：缺少所需输出入口 |
| v2（Tyranor/Rev.3049/emote） | 是 |
| v3（Tyranor/Rev.3201/emote） | 是 |
| V1（TyranorNext/Rev.2958） | 是 |
| V3（TyranorNext/Rev.3288） | 是 |
| V4（TyranorNext/Rev.3294/emote） | 是 |

内部版本值只是库选择标识，不能将用户界面版本统称为 V1–V6。自动回退到不支持的版本时不启用滤镜。尺寸可信前不统计为原始帧。

自研 Artemis 的画质增强接入等待 [artemis-compat PR #11](https://github.com/Weiss-UltimateSavior/artemis-compat/pull/11) 合并。

## 独立滤镜贡献

`engine/src/main/graphicsfilters/*.json` 是各贡献的注册来源。构建生成纯 Java 目录，供协议、尺寸规划、GPU 执行、设置适配和性能色条读取。每个可选贡献独立携带稳定 ID、三语言菜单、简称/颜色、参数能力、原生倍率、内部输出限制、分块能力及旧配置迁移，移除该贡献不需要编辑共享枚举或名称映射。

新增滤镜按来源独立提交：

- Anime4K 五项扩展：双边均值 / 中值 / 众数降噪、Thin HQ、Darken HQ。固定来源与文件哈希见 `engine/patches/anime4k-extra-filters.json`；上游 MIT 许可文本随资源保留。
- CAS：固定 GPUOpen FidelityFX-CAS 来源、GLES 适配、锐度和缩放参数、六个旧预设映射、生成器及 MIT 许可；来源见 `engine/patches/cas-filters.json`。
- CuNNy2：七个可见 NVL 预设、两个仅供旧 wire 兼容的隐藏记录、原生 2X 与退休迁移、独立生成器及 LGPL-3.0-or-later 许可；来源见 `engine/patches/cunny2-filters.json`。重建模型源码和权重按该固定提交获取，不能据项目根许可证推定权重另有授权。

CAS / CuNNy2 生成器分别为 `tools/generate-cas-filters.py`、`tools/generate-cunny2-filters.py`。`--sources` 指向对应来源目录（含固定提交的 origin.json / tree.json 和所需文件）；使用 `--check` 核对已提交结果。普通 Android 构建直接使用已打包资源，不下载模型或执行 Python 生成器。许可证整理仅计本轮引入的上游，不重复统计原项目依赖；本机完整许可留档保留在项目外。

## 组合滤镜内存修正

问题原因：原生两倍模型之后接较大修复模型时，所有中间 RGBA16F 特征平面同时分配，整链超过预算并回退为默认 Resize。

修复方式：根据实际版本化读写生命周期复用中间平面；对声明了固定邻域的 CNN 使用带边界扩展的分块处理，并保留原生倍率和像素相位。整链预算包含输入预留与完整输出；同一 pass 的读平面不能作为写目标。真实 GPU 尺寸上限或完整输出超预算仍安全回退。

影响范围：共用 GLES 执行器及所有使用它的引擎。可选模型的分块能力与限制由自身定义提供。

测试结果：用户已在 Android 15 / 16 两台设备上完成多种 CuNNy2 → Anime4K 组合及其他功能验收，结果通过。本次提交整理之后的编译和独立审查另记于本机整理记录，不将整理前的验收冒充新构建实机结果。

## 审查修订验证

本轮根据 CodeRabbit 意见修正 Siglus 生命周期、官方 Artemis JNI 失败路径和启动识别开销。画质启动参数共用传输适配器；引擎选项复用 `EngineSettingsStore`，Intent 协议键复用 `LaunchContract`。节点移动按当前节点键查找位置并检查边界，参数确认按钮与保存使用同一完整校验结果。

本地验证执行默认 release 编译、画质配置与启动策略回归、官方库身份匹配/拒绝回归及 Siglus 帧门控和 viewport 回归。按要求未进行本轮实机测试；JVM 测试与静态复核不覆盖 Android Surface/EGL 的实际时序，不将此前样本验收计作本轮修复的实机结果。Android CLI 指定审查技能未提供，使用通用审查技能完成独立静态复核。
