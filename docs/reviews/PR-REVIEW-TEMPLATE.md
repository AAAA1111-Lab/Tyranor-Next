# PR 审核回复模板

面向 AI/人工在 GitHub PR 上发布的通用审核回复模板。默认依据仓库根 `AGENTS.md`、`SPEC.md`、`CONTEXT.md` 与相关实现证据。

## 使用说明

- 复制「模板正文」并替换 `{...}` 占位符；删除不适用的可选项（如 Mermaid、重点问题说明）。
- 级别定义：
  - `高`：阻断合并（正确性错误、数据丢失/损坏、编译或测试失败、明显回归）。
  - `中`：合并前需确认或修复（迁移行为变化、规范硬性约束违背、线程/生命周期风险）。
  - `低`：可后续改进（文案、文档、可读性、非阻塞性优化）。
- 每条问题必须给出**文件 + 行号**与可核对的证据；不确定的内容标注「待确认」，不要写「可能/也许」式的猜测。
- 代码链接格式：
  - PR 变更代码：`https://github.com/{org}/{repo}/blob/{head_sha}/{path}#L{start}-L{end}`
  - 基线/既有代码：`https://github.com/{org}/{repo}/blob/{base_branch}/{path}#L{start}-L{end}`
- 验证记录必须写**命令 + 结果**；未执行的检查（真机、UI、性能等）要明确写出来。
- 问题按影响从高到低排序；重点问题展开说明，其余问题一行一条。
- 结论摘要在最前，先回答「是否可合并 / 主要风险是什么」。
- 不写纯描述、纯表扬或无行动项的意见；「已核对无问题」只保留关键结论。
- 发布方式：

```bash
gh pr review <pr_number> --repo <org>/<repo> --comment --body-file <file>
```

仅当存在「高」级问题时才使用 `--request-changes`。

参考实例：[PR #123 的审核 review](https://github.com/Weiss-UltimateSavior/Tyranor-Next/pull/123#pullrequestreview-5623780290)。

## 填写检查清单

- [ ] 审查范围写明 PR head SHA 与基线分支
- [ ] 验证命令与结果已记录，未执行项已声明
- [ ] 结论摘要先回答是否可合并
- [ ] 每条问题都有级别、证据链接、可执行建议
- [ ] 问题按影响排序，重点问题展开、其余问题收敛为一行
- [ ] 文档/规范类问题与代码正确性问题分开
- [ ] 「已核对无问题」只列关键结论，不写空泛表扬
